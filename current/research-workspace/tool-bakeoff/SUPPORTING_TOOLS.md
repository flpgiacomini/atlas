# Supporting Tools — shortlist after bake-off research

## Adopt / strongly recommended

### Zotero
Use for bibliographic/web source capture and source organization.
Do not duplicate the full bibliographic-management problem inside Atlas.

### OpenRefine
Use before canonical imports for:
- cleaning names;
- deduplication;
- entity reconciliation;
- Wikidata identifiers;
- batch preparation;
- Wikibase uploads if Wikibase is selected.

The five-case merge already proved this need when `Turbocharging` was independently created by two pilots.

### Tropy
Add as **optional research-photo workspace**, not a core dependency.
It is free/open source, stores projects in SQLite, supports custom metadata and exports JSON-LD/CSV.
Useful when the Atlas begins accumulating photographs of catalogues, advertisements, museum labels, archive documents or historical imagery.

## Keep for specific future needs

### Recogito
Useful for annotating historical texts/images and identifying places.
Potentially useful for extracting entities from period catalogues or historical maps.
Do not include in the normal workflow yet.

### Omeka S / CollectiveAccess
Museum/exhibition and collection-publication candidates.
Good if the public-facing Atlas later needs an archival/museum layer.
Not canonical knowledge stores for v1.

### Arches
Very capable open-source cultural-heritage/geospatial platform.
Defer: enterprise-level and geospatially oriented, too heavy for the current personal Atlas.

## Principle
A supporting tool enters the default workflow only when it removes a recurring manual burden.
Having a relevant feature is not enough.
